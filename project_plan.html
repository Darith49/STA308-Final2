University Data Portal: Complete Project Plan

Pitch: From messy Excel files to trusted, visual insights in one click. Assumptions: solo or 2-person team, 8 weeks, Django 5 + PostgreSQL, Chart.js as the core charting, Superset optional. Change these if your instructor says otherwise.

1. Overview

Problem: Universities keep student, grade and attendance data in inconsistent Excel files (typos, duplicates, mixed formats). Analysis is slow and error-prone.

Solution: A role-based web portal where staff upload XLSX files; the backend validates and cleans them, stores clean data, reports what it fixed, and powers live dashboards.

Objectives

  1. Secure login with role-based access
  2. XLSX upload with strict validation
  3. Automatic, explainable cleaning (every change reported)
  4. Normalized database with traceability to the source upload
  5. Role-scoped dashboards with live Chart.js charts
  6. Tested, documented, deployed system

Out of scope: arbitrary spreadsheet layouts (fixed templates only), mobile app, payments, real student information system integration.

2. Users and Permissions

Admin Yes Yes Yes Yes Yes
Registrar (data officer) Yes Yes Yes No Own only
Dept Head / Lecturer No No Yes No No

Implementation: Django Groups + Profile(user, role, department). Enforce through a reusable mixin/decorator on every view and API endpoint. Never rely on hiding buttons in templates.

3. Requirements

Functional

  • FR1 Register/login/logout, password reset, admin creates users
  • FR2 Download template per dataset type
  • FR3 Upload XLSX (Students, Courses, Grades, Attendance)
  • FR4 Validate file: extension, size ≤ 5 MB, opens with openpyxl, required headers present
  • FR5 Clean data automatically per dataset type
  • FR6 Save valid rows; store rejected rows with reason
  • FR7 Cleaning report page and downloadable error XLSX
  • FR8 Upload history with status (pending, processing, done, failed)
  • FR9 Dashboards with KPIs and charts, filters by department/semester/program
  • FR10 Searchable, paginated record tables with CSV export
  • FR11 Delete an upload and roll back its rows
  • FR12 Audit log of uploads and deletions

Non-functional: page loads < 2 s on 10k rows; 5k-row file processed in < 30 s; passwords hashed; HTTPS in production; 80%+ test coverage on cleaners; responsive layout.

7. Cleaning Pipeline

Location: services/cleaners/ (base + one cleaner per dataset) and services/importers.py. Cleaners are pure functions: DataFrame in, (clean_df, errors, report) out. No Django imports, so they are easy to test.

Stage 1: structural (base cleaner)

  1. Normalize headers: strip, lowercase, spaces → underscores, map known aliases ("Student ID", "ID No" → student_id)
  2. Drop fully empty rows/columns
  3. Trim whitespace in all text cells
  4. Remove duplicate rows (by business key), keep last, count them

Stage 2: type conversion

  • Numbers: pd.to_numeric(errors="coerce")
  • Dates: pd.to_datetime(errors="coerce", dayfirst=<configurable>)
  • Text: title-case names, upper-case codes

Stage 3: standardization

  • Category maps: {"cs": "Computer Science", "comp sci": ..., "m": "Male", "f": "Female"}
  • Attendance: present/p/1 → P, absent/a/0 → A, late/l → L

Stage 4: validation (row-level, errors are stored not silently dropped)

Rule Action
student_id missing reject row
score outside 0-100 reject row
year outside 1-6 set null + warning
email malformed set null + warning
date in the future reject row
unknown student/course FK reject row
missing gender/program fill "Unknown" (documented)

Missing-value policy (write this in your report): identifiers → reject; critical numeric (score) → reject; optional categorical → "Unknown"; never fill scores with averages because it distorts analysis.

Stage 5: import transaction.atomic() → bulk_create(batch_size=500) → save UploadError rows → write report → set status.

Report JSON example

{"rows_in": 1200, "empty_rows_removed": 14, "duplicates_removed": 22,
 "invalid_scores": 9, "unknown_students": 3, "dates_fixed": 41,
 "categories_standardized": 67, "rows_ok": 1148, "rows_rejected": 52}

Extras: file-hash duplicate detection ("this file was already imported"); preview of the first 20 cleaned rows before confirming (stretch); downloadable error XLSX.

9. API Design

GET /api/kpis/?dept=&semester=
GET /api/charts/students-by-department/
GET /api/charts/year-distribution/
GET /api/charts/enrollment-trend/
GET /api/charts/grade-distribution/?course=&semester=
GET /api/charts/pass-rate-by-course/?semester=
GET /api/charts/attendance-trend/?course=
GET /api/uploads/<id>/status/

Rules: every queryset passes through scope_for(user), which filters by department for non-admin roles. Return {labels: [], datasets: [...]} so the JS is generic. Use annotate/aggregate, select_related, and short caching (30-60 s) for expensive charts.

10. Dashboards

Admin/Registrar: KPI cards (students, courses, avg score, uploads this month, last upload status); bar (students per department); doughnut (gender or year); line (enrollment by year); table (recent uploads).

Department Head: histogram (score distribution), bar (pass rate by course), line (attendance over weeks), top/bottom 5 courses table.

"Live" behavior: (1) polling /status/ every 3 s during processing, then chart.update() with new data; (2) filter changes re-fetch via fetch(); (3) stretch: Django Channels pushes upload_done to open dashboards.

Superset (optional page "Advanced analytics"): Docker service reading the same PostgreSQL; create read-only DB user and 2-3 dashboards; embed via iframe or the embedded SDK. Check current Superset docs for guest-token setup, as it varies by version. Start only after MVP is stable.

11. Security Checklist

  • Django auth, LOGIN_REQUIRED default via middleware
  • Server-side role checks on all endpoints; test them
  • Validate uploads: extension, MIME sniffing, size, cell count limit, openpyxl open in read_only=True
  • Store uploads outside static/public paths; randomize filenames
  • Reject XLSX with macros or external links (.xlsm not accepted)
  • Prevent formula injection on export (prefix cells starting with =,+,-,@ with ')
  • CSRF, secure cookies, DEBUG=False, ALLOWED_HOSTS, HTTPS, secrets in .env
  • Login rate limiting (django-axes)
  • Audit log; regular DB backups

API response shape, scoping, filters DRF APIClient

Performance 10k-row file timing, query count assertNumQueries

Target: 80%+ coverage on services/, a test for every role-permission pair, and a test log table in your report.
